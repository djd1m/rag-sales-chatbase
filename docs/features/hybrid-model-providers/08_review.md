## Первый проход

Вердикт: runtime **blocker/high не найдено**. Есть одна **medium** находка в тестах:

- `tests/model-providers.test.ts:103–108`: `it.each([[...], ...])` разворачивает элементы строки в отдельные аргументы. Обработчик `async(data)` получает один объект embedding, поэтому все кейсы отвергаются на `!Array.isArray(data)`. Дубликаты, диапазон и отсутствующий `index` фактически не проверяются. Исправить на `{data:[...]}` и `async({data})`.
- Там же строка 27: `delete env.DEEPSEEK_API_KEY` для выведенного обязательного свойства может нарушить strict typecheck — объявить `env: NodeJS.ProcessEnv`.

Проверено чтением кода:

- Четыре сочетания провайдеров маршрутизируются раздельно; embedding-адаптер не перезаписывает `complete`.
- Адреса API фиксированы, редиректы запрещены, ошибки очищены от содержимого/ключей, автоматического fallback нет.
- DeepSeek payload соответствует свежей публичной [спецификации Responses](https://api-docs.deepseek.com/api/create-response/): входные сообщения могут обходиться без `type`, `text.format` поддерживает JSON Schema, `reasoning.effort=none`.
- Worker не получает DeepSeek-ключ. Однако общий `x-model-env` продолжает передавать ему заполненный OpenRouter-ключ даже при выбранном Cloud.ru; это следует учитывать в формулировках документации.
- Квота → attempt/fsync → вызов, лимиты проб, порог до генерации, проверка цитат после, изоляция ботов и размерность 1536 сохранены.

Файлы не изменял, секреты не читал, платные запросы и отдельный тестовый прогон не выполнял. Живую совместимость API и качество ответов это ревью не доказывает.
