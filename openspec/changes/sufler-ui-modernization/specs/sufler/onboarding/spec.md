## ADDED Requirements

### Requirement: Явный выбор источника
Система SHALL показывать выбор «Сайт / PDF», ограничения и необходимость входа для PDF до начала действия. Публичный сайт продолжает обрабатываться существующим preview-контуром до регистрации. Трассировка: UI FR-2.

#### Scenario: PDF до входа
- **GIVEN** посетитель выбрал PDF без сессии
- **WHEN** проходит вход или регистрацию
- **THEN** точное разрешённое намерение `/dashboard?source=pdf` сохраняется и ведёт к выбору настоящего бота либо его созданию в пределах плана

#### Scenario: Прочий next
- **GIVEN** next содержит произвольную внешнюю ссылку, неподдерживаемый путь или иной query
- **WHEN** завершается вход
- **THEN** серверные и клиентские ограничения не дают open redirect и не обходят владение ботом

### Requirement: Короткий первый запуск с ручной альтернативой
Система SHALL показывать в пустом кабинете путь «Материалы → Проверка → Установка», один основной старт с сайта и доступную раскрываемую ручную форму. Трассировка: UI FR-3.

#### Scenario: Ручной способ
- **GIVEN** список ботов пуст
- **WHEN** пользователь раскрывает ручное создание
- **THEN** доступны прежние поля и серверные ограничения; сворачивание не теряет корректный ввод

### Requirement: Фактический исход сохранения после входа
Система SHALL показывать установленный результат claim из фактического ответа auth/claim, сопряжённого с текущей проверенной сессией, одноразово в текущей вкладке. Выбор PDF сохраняется отдельно. Состояния материалов, ответов, кода и установки берутся из своих контрактов. Система MUST NOT создавать дополнительного бота только из-за возврата к PDF и MUST NOT придумывать botId, отсутствующий в ответе авторизации. Трассировка: UI FR-2, FR-3, FR-4, NFR-3.

#### Scenario: Вход с failed preview
- **GIVEN** при входе существующий auth-контур сохранил предпросмотр, включая отказавший
- **WHEN** пользователь продолжает с PDF
- **THEN** видит исход сохранения и реальные доступные боты; при нескольких выбирает нужного без автоматического дублирования

#### Scenario: Флаги URL, повтор и смена сессии
- **GIVEN** пользователь открывает прямой `saved=1`, повторяет законченный переход или меняет сессию после предшествующего ответа
- **WHEN** открыт кабинет с PDF-намерением или без него
- **THEN** сохранение не утверждается без свежего одноразового контекста фактического ответа, совпадающего с текущей сессией

#### Scenario: Сохранение не состоялось
- **GIVEN** действительный ответ текущей сессии сообщает предел ботов или временную недоступность
- **WHEN** пользователь завершает вход и продолжает к PDF
- **THEN** видит соответствующий отказ и доступные действия, выбор PDF сохраняется, новый бот не создаётся автоматически

### Requirement: Действующие сценарии доступа
Система SHALL сохранять show/hide пароля и ссылки на реальные recovery/verify маршруты customer-trust. Подтверждение почты MUST NOT становиться новым условием доступа к PDF-кабинету; оно требуется для нового checkout по отдельному контракту. Трассировка: UI FR-4.

#### Scenario: Неподтверждённый владелец
- **GIVEN** действующий аккаунт вошёл, но email не подтверждён
- **WHEN** открывает PDF-намерение
- **THEN** кабинет доступен по прежней авторизации, а будущая покупка отдельно объясняет подтверждение почты
