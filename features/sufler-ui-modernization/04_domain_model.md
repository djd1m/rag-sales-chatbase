# Доменная модель обновления интерфейса Суфлёра

Черновик для focused QCSD, 25.11.2026. Уточнён после исходного независимого ревью.

## Bounded context map

| Существующий контекст | За что отвечает в обновлении |
|---|---|
| Публичный предпросмотр | Читает сайт в пределах предпросмотра, связывает задачу с браузером и отдаёт состояние, результат и право сохранить черновик. |
| Кабинет владельца | Ведёт принадлежащих владельцу ботов, источники, контакт компании, просмотр ответов, действия публикации и установки. |
| Вход и customer-trust | Устанавливает действительную сессию, проверяет адрес продолжения. В своём контексте подтверждает почту, восстанавливает доступ и даёт поддержку. |
| Планы и оплата | Ведёт цену и доступ, лимиты ответов, срок, признак подписи и правила оформления. |
| Ответы и внешний виджет | Выбирает допустимый подтверждённый фрагмент или возвращает иной штатный результат. Внешний виджет проверяет разрешённый origin и состояние активации бота. |

Новый интерфейс объединяет действия этих контекстов в маршрутах пользователя. Границы хранения и авторизации действуют по прежним контрактам.

## Ubiquitous language

| Понятие | Значение в сценарии |
|---|---|
| Источник | Публичный сайт, PDF или текстовый файл существующего бота. На публичном старте доступны выбор сайта либо переход к авторизованному PDF. |
| Предпросмотр | Временный черновик для сайта с браузерной сессией. Даёт проверить результат до сохранения в кабинет. |
| Задача | Серверная работа с `index_job_id`. Статус определяет, продолжается ли чтение, готов ли ответ, давно ли нет обновлений, завершилась ли задача с ошибкой. |
| Выбор PDF | Намерение найти в кабинете поле файла своего бота. Возврат идёт на `/dashboard?source=pdf`. Сам файл появляется только после выбора в защищённой форме. |
| Возврат к адресу | Режим редактирования после задачи. `jobId` связывает поле с краткоживущим безопасным корневым origin в своей вкладке. Сложный адрес вводится вручную. Запуск требует подтверждения. |
| Исход сохранения | Факт перехода черновика в кабинет или причина, по которой переход не состоялся. При входе API сообщает статус, при явном успешном claim возвращает `bot_id`. Одноразовое уведомление использует фактический ответ и текущую серверную сессию. Готовность материалов, включённые ответы, код и установка имеют собственные факты. |
| Источник ответа | Серверные название, фрагмент и допустимая ссылка конкретного `answered`. Первая цитата открыта при появлении ответа. Для `unknown` сохраняется штатное объяснение и доступный контакт или уместный шаг настройки. |
| Отметка сценария | Локальное действие владельца в тестовом чате. Для трёх отдельных случаев хранится набор отметок текущего экрана. |
| Подтверждение ответов владельцем | Серверное действие `verify`, влияющее на ответы виджета. Подтверждение email действует в контексте аккаунта и нового checkout. |
| Установка | Выданный сервером тег, вставка на разрешённом внешнем origin и отдельная проверка работы. Серверный факт подтверждённого первого ответа отличается от факта копирования тега. |

## Aggregates, entities and value objects

| Граница | Сущности, значения и инвариант |
|---|---|
| Предпросмотр и созданная задача | `preview` со своей браузерной сессией, черновой `bot`, `index_job` и сроком жизни. Создание с квотой и идемпотентностью, а также дальнейшее сохранение используют существующие транзакции. Повтор использует прежний ключ. |
| Владелец и набор ботов | `account` и принадлежащие ему `bot`. Создание и claim используют уже существующую общую блокировку account и предел плана. PDF, вопрос, настройки и установка проверяют принадлежность. |
| Материалы и работа виджета | `source`, `index_job`, состояние `answers_verified`, контакт, разрешённый origin. `widget_install` записывает внешний `first_config` и первый подтверждённый `first_answer`, сохраняя отдельность от этапов настройки. |
| Платный доступ | Закрытые `free`, `nobadge`, `studio` и фактические активные условия. Открытый экран тарифов читает представление цены и квот, не меняя их. |
| Значения экрана | Режим разобранного query, ограниченная пара `jobId`/безопасный origin, непрозрачный ключ запуска, одноразовый контекст исхода claim, выбранный ответ и локальные отметки. Хранилище браузера не участвует в авторизации. Состояние сбрасывается при смене задачи, бота или сессии по своим контрактам. |

Экранное представление использует действующие DTO `PreviewJobView`, `ChatMessage`, `OwnerMessage`, `SourceView` и `PlanAnswers`. Для локальных отметок, выбора PDF и адреса возврата не добавляются сущности БД или события модели.

## Relationships

[Карта контекстов](diagrams/domain-model.mermaid). Публичный предпросмотр и кабинет являются потребителями контрактов ответов, хранилища и планов. Кабинет и вход обмениваются ограниченным адресом продолжения и фактом сохранения. Внешний виджет использует опубликованный контракт домена и ответа владельца. Отношения описывают имеющиеся зависимости, в том числе общий серверный код auth и claim.
