## ADDED Requirements

### Requirement: Выполнимое продолжение после ошибки
Система SHALL показывать причины сбоя и реально доступные действия. Упоминание PDF MUST сопровождаться переходом в действующий PDF-сценарий. Предзаполнение URL после ошибки MUST NOT запускать повторное чтение без явного подтверждения. Трассировка: UI FR-6.

#### Scenario: Отказ чтения сайта
- **GIVEN** сервер сообщил failed, robots или иной поддерживаемый отказ
- **WHEN** пользователь выбирает повтор с другим адресом
- **THEN** безопасный корневой origin восстанавливается только из свежего контекста текущей вкладки с тем же jobId, а новый запрос требует явной отправки

#### Scenario: Контекст отсутствует
- **GIVEN** адрес для jobId не сохранён или недоступен storage
- **WHEN** открыт повтор
- **THEN** форма остаётся рабочей с пустым полем, чужой URL не подставляется

#### Scenario: Первый GET недоступен или завершённому заданию не хватает сайта
- **GIVEN** первый запрос статуса временно не удался или `done` вернул `site: null`
- **WHEN** пользователь видит соответствующее состояние и выбирает «Проверить состояние»
- **THEN** выполняется только GET для того же `jobId`, при `done` с валидным `site` открывается чат, при `404` опрос прекращается, ни вопрос, ни создание задачи не отправляются

### Requirement: Минимальный контекст адреса сайта
Новые формы SHALL передавать адрес в теле явного POST. Адрес, допускаемый только как значение штатного запроса, MUST NOT сохраняться в браузерном контексте. Для повторной попытки безопасного корневого адреса SHALL использоваться прежний непрозрачный UUID в ограниченном по объёму и сроку хранилище вкладки. Трассировка: UI FR-2, FR-6, NFR-3, NFR-4.

#### Scenario: Адрес с секретными частями
- **GIVEN** адрес содержит userinfo, произвольный path, query или fragment
- **WHEN** отправляется форма или обрабатывается прежний `?url`
- **THEN** userinfo отклоняется, секретные части отсутствуют в новых навигациях и browser storage, поддерживаемый сложный адрес доступен только текущей явно отправленной форме, а восстановление предлагает ручной ввод

#### Scenario: Совместимый повтор безопасного корневого адреса
- **GIVEN** обычный прежний `?url` или прерванная попытка допустимого корневого адреса
- **WHEN** открывается legacy запуск либо повторяется явная отправка
- **THEN** legacy вход инициирует один запрос и очищает параметр истории, безопасный повтор использует прежний UUID, старые сырые ключи очищаются

### Requirement: Проверка конкретных ответов
Система SHALL сохранять реальные источники, unknown, контакт компании и серверное разрешение работы бота. Первая подходящая цитата в обоих чатах владельца SHALL быть видна без дополнительного действия. Локальные отметки сценариев MUST относиться только к текущей проверке и MUST NOT заменять `verified`, публикацию или доказательство общего качества. Трассировка: UI FR-7.

#### Scenario: Цитата при первом ответе
- **GIVEN** в одном из чатов владельца появился первый `answered` с цитатой
- **WHEN** пользователь смотрит ответ на широком или мобильном экране
- **THEN** текст источника уже виден; клавиатурный выбор другой цитаты сохраняет черновик и одну доступную панель

#### Scenario: Локальная отметка
- **GIVEN** владелец отмечает проверку фактического ответа, неизвестного вопроса или контакта
- **WHEN** меняет отметки
- **THEN** они не вызывают платный запрос и не включают ответы посетителям сами по себе

#### Scenario: Нет подходящих сведений
- **GIVEN** существующий контур вернул unknown
- **WHEN** результат отображается
- **THEN** UI сохраняет честное отсутствие ответа и доступный контакт без выдуманной цитаты

#### Scenario: Первый unknown без контакта
- **GIVEN** результат `unknown` не содержит доступного контакта
- **WHEN** его видит гость, вошедший в несохранённом предпросмотре или владелец в кабинете
- **THEN** ему доступны соответственно обычный вход, явное сохранение черновика для настройки или настройки своего бота; показ не запускает claim и не имитирует `first_answer`

### Requirement: Установка проверяется отдельно от копирования
Система SHALL различать фактическое наблюдение наполненного экрана установки на изолированном стенде, копирование кода и результат на собственном разрешённом внешнем origin. До приёмки FR-9 SHALL быть записано отдельное свидетельство такого наблюдения и решение о необходимости новой правки. Трассировка: UI FR-9.

#### Scenario: Код скопирован
- **GIVEN** готовый бот на изолированном стенде и разрешённый домен
- **WHEN** пользователь копирует код
- **THEN** интерфейс сообщает о копировании; без события или явной ручной проверки не заявляет подтверждённую установку

#### Scenario: Заполненный стенд и внешний origin
- **GIVEN** собранное приложение и собственный тестовый бот с материалами и разрешённым отдельным origin
- **WHEN** настоящий тег стенда установлен на тестовой странице и открывается чат
- **THEN** отчёт отдельно фиксирует визуальные этапы, `first_config`, доступность `first_answer` и использованную синтетическую модель; проверка компонентов не заменяет наблюдение
