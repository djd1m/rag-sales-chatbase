# Проект обновления интерфейса Суфлёра

## Context

Действующие маршруты, статусы, квоты и цены задают поведение. Альбом от 25.11.2026 задаёт визуальное направление. Изменения по восьми условиям исходного QCSD подготовлены для независимой focused verification.

## Goals / Non-Goals

Цели — видимый запуск на коротком экране, понятный выбор источника, восстанавливаемый опрос и проверка реальных ответов. UI сохраняет серверные факты и действующий доступ. Расчёт цен и квот, модель, серверная верификация, хранилище файлов и новый экран установки остаются за рамками этого изменения.

## Decisions

- Новые формы используют адрес в теле клиентского `POST /api/preview`. Наследуемый `/preview?url=…` сохраняет однократный запуск допустимого адреса и удаляет `url` из строки. Ветка PDF/retry всегда без автостарта. Хранилище сохраняет хэш только нормализованного безопасного корневого origin, UUID и свежую привязку `jobId` к origin. Поддерживаемый сложный адрес остаётся в памяти попытки. Имена старых ключей очищаются. Userinfo отклоняется до запроса.
- `next=/dashboard?source=pdf` допускается точным сравнением. Одноразовый результат входа или claim связывается с текущей сессией через дополнительный `X-Sufler-Claim-Context`, существующий JSON и статусы сохранились в проекте. Браузерный slot живёт до двух минут, потребляется один раз и не даёт доступа. Флаги `saved`/`preview` в адресе не устанавливают результат.
- Отказ проверки статуса и `done/site:null` дают отдельное действие GET в рамках той же задачи. `404` прекращает опрос. Источник первого `answered` сразу раскрыт у владельца, с одной доступной активной панелью на любом размере. `unknown` использует настоящий контакт или следующий шаг, соответствующий сессии, отдельно от `first_answer`.
- Аудит U09 использует заполненный тестовый аккаунт, реальный Next-маршрут, рабочий тег стенда, управляемый внешний origin и синтетическую модель при необходимости положительного ответа. Подмены, реальные серверные события и наблюдаемые экранные результаты указываются в квитанции отдельно.

## Risks / Trade-offs

Открытие старой ссылки уже содержит данные первого GET. Новый путь и контекст storage используют минимальные значения. Без storage сохранение и PDF продолжаются с актуальными данными кабинета, короткий баннер может быть недоступен. Проверка с двумя сессиями покрывает ошибочный перенос результата. При позднем сбое опроса прежний прогресс обозначен как последний известный.

## Migration Plan

БД и контракты моделей не меняются. При доступе к браузерному состоянию старый префикс очищается, совместимый UUID переносится лишь для текущего безопасного корневого адреса. Ввод заголовка, AuthForm и чтение актуальной сессии координируются между UI и customer-trust. Существующая оболочка получает рабочие ссылки через одного писателя.

## Open Questions

До приёмки сохраняются результаты независимого focused review и исполняемых тестов, а также отдельное наблюдение установки U09. Реализация на этой стадии ещё не подтверждена.
