# Практики UX для Суфлёра

Проверено 25.11.2026 отдельным исследовательским роем из трёх ролей: первый запуск, доверие к ИИ, мобильные формы и доступность. Это исследование первоисточников, а не независимое тестирование приложения этими агентами. Живые экраны исследовал основной агент в выделенном контейнере.

Рекомендации ниже связаны с карточками визуального альбома. Приоритеты и критерии — предложения команды; измеренного влияния на конверсию нет.

| Практика | Применение в Суфлёре | Карточки / статус |
|---|---|---|
| Короткий путь до первого результата | Показать последовательность «Материалы → Проверка → Установка»; оставить один основной следующий шаг | U03, кандидат |
| Подсказки рядом с вводом | Подпись поля остаётся видимой, пример URL и ограничения PDF находятся рядом с выбором | U02, часть подписей уже есть |
| Дополнительные возможности по потребности | Ручное создание и необязательные параметры раскрывать после понятного начала | U03, кандидат |
| У ошибки есть выполнимое продолжение | Если предлагается PDF, рядом должен быть переход к нему, включая необходимый вход | U06, воспроизведена несогласованность |
| Продукт виден до регистрации | Пример ответа и его источника рядом с главным действием | U01, гипотеза композиции |
| Вход помогает восстановить доступ | Видимость пароля и полный сценарий восстановления, а не декоративная ссылка | U04, потребует отдельной реализации |
| Условия понятны до выбора плана | Объяснить назначение плана и подпись простыми словами; реальные цены и условия сохранить | U05, гипотеза понятности |
| Источник помогает проверке, но не заменяет её | Сохранить цитаты и дать владельцу проверить фрагмент рядом с ответом | U07, источник уже отображается |
| Неизвестный ответ — полноценное состояние | Сохранить объяснение нехватки сведений и контакт компании | Уже есть в UI; проверено на подменённых ответах |
| Обработка, готовность и сбой различимы | Показывать реальные этапы и доступные дальнейшие действия; не рисовать вымышленные проценты | U06 и концепт обработки |
| Копирование кода не равно установке | Отдельно проверить появление виджета и тестовый ответ на внешней странице | U09, сначала нужен аудит действующего экрана |
| Мобильный первый шаг остаётся достижимым | Сохранить хороший reflow, сократить первый экран на 320×568 | U08; на 375×667 и 390×844 CTA уже виден |

## Почему эти направления

**Первый запуск и подсказки.** USWDS рекомендует индикатор для понятной последовательности крупных этапов. NN/g описывает постепенное раскрытие как способ не показывать все дополнительные возможности одновременно; длинные обучающие туры не заменяют помощь в момент действия. Для Суфлёра это означает короткий сценарий, а не копирование всего меню более широкого продукта. [USWDS Step indicator](https://designsystem.digital.gov/components/step-indicator/), [NN/g Progressive disclosure](https://www.nngroup.com/articles/progressive-disclosure/), [NN/g Onboarding tutorials](https://www.nngroup.com/articles/onboarding-tutorials/).

**Ввод и ошибки.** Постоянные подписи и понятные подсказки помогают подготовить данные. При ошибке GOV.UK предлагает согласованное сообщение рядом с полем и в сводке со ссылкой на поле. В текущем публичном интерфейсе подписи уже есть; полная сводка нужна по сложности формы, а не автоматически для каждого одиночного поля. Введённые корректные данные следует сохранять. Для file-input нельзя обещать восстановление очищенного выбора файла. [Text input](https://design-system.service.gov.uk/components/text-input/), [File upload](https://design-system.service.gov.uk/components/file-upload/), [Error summary](https://design-system.service.gov.uk/components/error-summary/), [Validation](https://design-system.service.gov.uk/patterns/validation/).

**Доверие к ответам.** Google PAIR рекомендует объяснять используемые сведения и давать понятный путь при ошибке. Microsoft HAX — обозначать поддерживаемые задачи и границы возможностей. Для Суфлёра уже существующие источники и контакт важнее декоративного обещания «точных ответов». Новый чек-лист не является гарантией качества всех будущих ответов. [PAIR Explainability + Trust](https://pair.withgoogle.com/guidebook-v2/chapter/explainability-trust/), [PAIR Errors + graceful failure](https://pair.withgoogle.com/guidebook-v2/chapter/errors-failing/), [HAX: возможности системы](https://www.microsoft.com/en-us/haxtoolkit/guideline/make-clear-what-the-system-can-do/).

**Ожидание и установка.** Динамическое сообщение о состоянии должно быть доступно без перемещения фокуса. Визуальное «копирование выполнено» не доказывает появление виджета на странице клиента. Автоматическое подтверждение допустимо только при поддержке реальных событий; иначе нужен явно обозначенный ручной шаг. [W3C Status messages](https://www.w3.org/WAI/WCAG22/Understanding/status-messages.html), [USWDS Process list](https://designsystem.digital.gov/components/process-list/).

**Доступность.** WCAG 2.2 AA 2.5.8 задаёт цель 24×24 CSS px с исключениями, включая допустимое расстояние между целями. 44×44 CSS px относится к AAA 2.5.5; в нашем проекте это удобная цель для основных кнопок, а не универсальный минимум AA. Для обычного текста ориентир AA — 4,5:1, крупного — 3:1. Видимый фокус и отсутствие горизонтального переполнения проверяются отдельно. Попадание CTA в первый экран — UX-цель этого макета, не требование WCAG. [Target size AA](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html), [Target size AAA](https://www.w3.org/WAI/WCAG22/Understanding/target-size-enhanced.html), [Contrast](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html), [Focus visible](https://www.w3.org/WAI/WCAG22/Understanding/focus-visible.html), [Reflow](https://www.w3.org/WAI/WCAG22/Understanding/reflow).

## Что подтверждено у Chatbase

Его публичная документация связывает добавление материалов, тестирование и установку. В Playground рекомендуются обычные вопросы, вопрос без ответа в базе и проверка контакта человека. Это полезный ориентир для сценария владельца Суфлёра. [Первый агент](https://www.chatbase.co/docs/user-guides/quick-start/your-first-agent), [Playground](https://www.chatbase.co/docs/user-guides/chatbot/playground), [Data Sources](https://www.chatbase.co/docs/user-guides/chatbot/data-sources), [Channels](https://www.chatbase.co/docs/user-guides/chatbot/channels).

Сравнение не подразумевает, что Chatbase обеспечивает полную изоляцию любых изменений: документация версий оговаривает особенности источников и обучения. Настоящее версионирование базы — отдельная backend-задача, не результат перестановки элементов UI. В предложенных макетах такая функция не объявляется готовой. [Drafts and versions](https://www.chatbase.co/docs/user-guides/chatbot/versions).

## Как затем проверить пользу

После выбора направлений подготовить задачи для владельцев малого бизнеса: добавить первый источник, проверить фактический ответ и отсутствие сведений, найти восстановление доступа, установить виджет на тестовую страницу. До теста зафиксировать критерии: завершение задачи, время, лишние переходы, ошибки и потребность в подсказке. Сравнить текущую версию и выбранный прототип на одинаковых задачах. Числа конверсии и выигрыша появятся только после такого измерения.

Изображения закрытых экранов Chatbase в альбоме — официальные иллюстрации, не результат входа в его кабинет. Происхождение и дата получения — `reference-provenance.json`; дата исходной съёмки не заявляется.
