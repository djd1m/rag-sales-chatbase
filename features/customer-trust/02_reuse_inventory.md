# Инвентаризация customer-trust

Исследование и черновик требований для шагов 1–2 feature-adr, 25.11.2026. Для ADR, OpenSpec и плана реализации.

Владелец подтвердил реквизиты из Clipmkr и отдельный канал Суфлёра в существующей службе поддержки. Публичные реквизиты берутся из утверждённых разделов privacy/terms Clipmkr. Условия продажи и обработки данных Суфлёра описываются по его собственным правилам.

- Clipmkr `djd1m/clipmkr` на `d35c15bdbf3f01e4188d4a7494f06bc021b38906`. Исходники и дерево сверены через GitHub API по SHA. ## Провайдеры и ограничения standalone VPS

Проверка наличия переменных выполнена в локальном `.env` и активном web-контейнере Суфлёра. В таблице показаны только признаки непустых значений. Платёжный отдел, аккаунт отправителя, DNS и рабочий входящий канал этой проверкой не подтверждаются.

| Переменные | `.env` | web | Контракт |
| --- | --- | --- | --- |
| `N6_PAYMENTS_MODE` | задана | задана | Действующее имя. `off` даёт экран интереса. `live` использует ЮKassa и требует явных параметров магазина. `fake` запрещён в production. |
| `YOOKASSA_SHOP_ID`, `YOOKASSA_SECRET_KEY`, `YOOKASSA_TEST_MODE` | отсутствуют | отсутствуют | Действующие имена. `live` при таком наборе не проходит проверку. `YOOKASSA_TEST_MODE` определяет, с каким видом магазина должна совпадать проверка провайдера. |
| `N6_MAIL_MODE`, `N6_RESEND_API_KEY`, `N6_MAIL_FROM` | отсутствуют | отсутствуют | Предлагаемые имена. `N6_MAIL_MODE=disabled\|resend`. Для `resend` обязательны серверный ключ и отправитель на проверенном домене. Общая переменная `RESEND_API_KEY` также отсутствует, договорённости о совместном использовании ключей нет. |
| `N6_SUPPORT_MODE`, `N6_SUPPORT_CONTACT_EMAIL`, `N6_PRIVACY_CONTACT_EMAIL` | отсутствуют | отсутствуют | Предлагаемые имена. `N6_SUPPORT_MODE=disabled\|libredesk`, по умолчанию `disabled`. `N6_SUPPORT_CONTACT_EMAIL` — опциональный подтверждённый резервный канал. Юридический контакт выбирается по согласованным публичным реквизитам и цели обращения. |
| `N6_SUPPORT_BASE_URL`, `N6_SUPPORT_INBOX_ID`, `N6_SUPPORT_JWT_SECRET` | отсутствуют | отсутствуют | При `libredesk` обязательны канонический HTTPS origin, UUID выделенного inbox Суфлёра, его собственный серверный ключ идентификации. Ключ не попадает в HTML или клиентский конфиг. Отдельное значение `IDENTIFIED` не требуется, активный канал идентифицирует только подтверждённый аккаунт. |

Предложение для фискальных настроек при подтверждении схемы «Чеки от ЮKassa». `N6_YOOKASSA_RECEIPTS_MODE=disabled|yookassa`, `N6_YOOKASSA_RECEIPT_VAT_CODE`, `N6_YOOKASSA_RECEIPT_PAYMENT_SUBJECT`, `N6_YOOKASSA_RECEIPT_PAYMENT_MODE`. `N6_YOOKASSA_RECEIPT_TAX_SYSTEM_CODE` добавлять при требовании выбранной схемы магазина. Значения согласовать отдельно для каждого контура. Формат `receipt` из Clipmkr применим для соответствующего кассового сценария. API ЮKassa также поддерживает отдельную отправку чека, конфигурацию магазина нужно установить до выбора контракта. [Чеки от ЮKassa](https://yookassa.ru/developers/payment-acceptance/receipts/54fz/yoomoney/payments), [сторонняя касса](https://yookassa.ru/developers/payment-acceptance/receipts/54fz/other-services/basics).

- ЮKassa документирует повтор с неизменным телом и ключом в течение 24 часов, а также проверку источника/статуса webhook. Дополнить существующую схему безопасным состоянием сверки и не использовать живой контур для тестовых платежей. [Формат API](https://yookassa.ru/developers/using-api/interaction-format), [уведомления](https://yookassa.ru/developers/using-api/webhooks).
- Resend HTTP — исходящий транспорт без нового процесса на VPS. Подтвердить отправляющий домен, ключ с минимальной областью доступа и отдельно проверить допустимость обработки email и маршрутизации для Суфлёра. Регион отправки не решает сам по себе вопрос обработки. Отключить трекинг в транзакционных письмах. Альтернатива — утверждённый внешний SMTP с TLS и проверяемой доставкой, если условия Resend не подходят. [Email API](https://resend.com/docs/api-reference/emails/send-email), [проверка домена](https://resend.com/docs/dashboard/domains/introduction), [обработка данных в Resend](https://resend.com/security/gdpr/).
- Поддержка использует выделенный inbox в существующем Libredesk, без развёртывания нового helpdesk на VPS. Публичный origin `https://support.clipmkr.ru` указан в закреплённом `deploy/support-widget-privacy.caddy:1` и `docs/research/support-access/runtime-metadata.md:9`. 25.11.2026 публичный HEAD `/` вернул HTTP 200. Это проверка доступности origin. Для работы Суфлёра нужны UUID собственного inbox, серверный ключ, разрешённый origin Суфлёра в виджете, правила доступа оператора и проверка изоляции истории между продуктами. [Origin поддержки в конфигурации Clipmkr](https://github.com/djd1m/clipmkr/blob/d35c15bdbf3f01e4188d4a7494f06bc021b38906/deploy/support-widget-privacy.caddy#L1), [контракт готовности виджета Clipmkr](https://github.com/djd1m/clipmkr/blob/d35c15bdbf3f01e4188d4a7494f06bc021b38906/openspec/changes/support-widget-readiness/specs/support-widget/spec.md).
- Бюджет VPS — 2 CPU и 4 GB. Базовые лимиты `compose.vps.yml:20–58` — web 0,75 CPU и 640 МиБ, worker-index 0,75 и 512 МиБ, PostgreSQL 0,50 и 384 МиБ, Redis 0,25 и 128 МиБ, внутренняя дверь 0,35 и 96 МиБ. Это квоты контейнеров, а не измерения. Держать сетевые обращения вне транзакций, ограничить тело, длительность, параллельность отправки и очистку партий. Chromium/Playwright запускать в выделенном контейнере, наружу выставлять только действующую дверь. [Ограничения VPS](../../deploy/vps/README.md).

## Черновик требований

Участники — гость, владелец сайта с новым или действующим аккаунтом, посетитель встроенного виджета, оператор поддержки и владелец Суфлёра. Здесь предложены критерии для согласования. Платёжный набор, тарифные права, способы списаний и политика обработки персональных данных определяются действующей продуктовой логикой и утверждёнными документами.

## Открытые вопросы

1. **Комплект документов.** Реквизиты оператора и продавца подтверждены владельцем, источник — публичные разделы Clipmkr. Для утверждения подготовить условия использования, описание платной услуги и порядка возврата (в соглашении или отдельной оферте по выбранной форме), политику обработки данных, отдельные тексты согласий по применимому основанию, раскрытие cookies/хранилищ и уведомление для посетителя виджета. Условия партнёрской/студийной программы и соглашение об обработке за владельца сайта включать по подтверждённой роли и объёму. Согласовать редакцию, перечень обработчиков, сроки, основания, регионы и процесс работы с обращениями. [Публичные реквизиты Clipmkr в privacy](https://github.com/djd1m/clipmkr/blob/d35c15bdbf3f01e4188d4a7494f06bc021b38906/apps/web/src/lib/legal-documents.ts#L58), [в условиях](https://github.com/djd1m/clipmkr/blob/d35c15bdbf3f01e4188d4a7494f06bc021b38906/apps/web/src/lib/legal-documents.ts#L151).
2. **Кассовый сценарий.** Требуются собственный изолированный магазин Суфлёра или подтверждённая отдельная конфигурация с маршрутизацией, тип кассы и нужные параметры каждого вида платежа/возврата: предмет, способ расчёта, НДС, при необходимости налоговый режим. Подтвердить применимость полного расчёта для платного доступа и порядок выдачи/проверки фискального чека. В текущем runtime параметры магазина отсутствуют, поэтому внешняя готовность остаётся открытой. На этапе подготовки не создавались платежи и письма.
3. **Почта и UX.** Подтвердить провайдера, домен, управление DNS, прикладной ключ, отправителя и допустимый процесс обработки данных. Выбрать запуск отправки по явному действию или после успешной регистрации, правила для смены адреса и переход из письма, если оно открыто на другом устройстве либо исходная сессия уже отозвана. Параметры TTL/cooldown и численные лимиты сверить с актуальными квотами и нагрузкой, ориентир референса — 24 ч для verify, 1 ч для reset и 60 с между выдачами на адрес.
4. **Поддержка.** Существующая служба и отдельный канал Суфлёра подтверждены. Для активации нужны UUID inbox, отдельный ключ, включение origin Суфлёра на стороне виджета, подтверждённая операторская маршрутизация и проверка разделения истории. Открыты резервный канал, процесс запроса возврата, обращений по данным и перечень допустимого контекста. Обещание сроков зависит от подтверждённого процесса.
5. **Переход и запуск.** Решить, когда требовать новую версию условий у существующих владельцев, как сверяются старые незавершённые платежи, нужен ли провайдерский TEST после локального QA и как отделён от LIVE. Синтетический контур проверяет основной контракт до конфигурирования внешних сервисов. Публикация документов, реальная отправка и боевые списания имеют отдельные фактические предпосылки. Для внедрения требуются ADR, OpenSpec, трассировка требований, K1/K2.
