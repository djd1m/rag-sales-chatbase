# Поправки автора к проекту UI после исходного QCSD

25.11.2026. Классификация `structural`. Зафиксированы проектные изменения для focused verification. Независимые заключения и host lineage остаются у исходных рецензентов и координатора. Ни одна из нижеперечисленных проверок реализации на этом этапе не выполнена.

| Условие | Изменение решения | Наблюдаемое подтверждение, предусмотренное проектом |
|---|---|---|
| Q-01 | Первый `503` заканчивает начальную заглушку. `done/site:null` получает отдельное завершённое состояние и останавливает автоматический опрос. Видимое действие выполняет один GET того же `jobId`. | Подать `503`, повторный отказ и успешный `done/site`, затем отдельный `done/null`. Проверить тексты, остановку/возобновление и ноль POST создания/вопроса. |
| Q-02 | Оба чата владельца сразу раскрывают первую серверную цитату. Выбор сообщения с клавиатуры переключает активный фрагмент, источник не дублируется в порядке Tab. | Два разных ответа, оба чата, узкое и широкое окно. Цитата видна без клика, прежний фрагмент доступен без потери истории или черновика. |
| Q-03 | Уведомление `claimed` сообщает только о сохранении. Материалы, включение ответов, код и установка остаются отдельными фактами. Выбор PDF идёт в реальный список принадлежащих владельцу ботов. | Войти с failed preview, сравнить с прямым `saved=1` при том же списке и с отказами. Первый даёт реальный исход, второй нет, причины отказа видимы. |
| Q-04 | `unknown` сохраняет серверный контакт. При его отсутствии видны настройки своего бота, явный claim для вошедшего или настоящий вход для гостя. Прежний CTA появляется только по фактическому `first_answer`. | Guest, signed-in unsaved и owner cabinet, с контактом и без него. Ноль вызовов `claim`, `ask`, `verify` и `publish` от отображения. |
| UI-T01 | Архитектура задаёт настоящий Next-маршрут, PostgreSQL, владельцев A/B, авторизованную область и preview cookie. Успешный ответ использует действительный контракт, транспортные отказы и `done/null` помечены подменами. | Матрица `running → done/site`, `503 → 503 → GET recovery`, `done/null`, поздний сетевой сбой, `404`, автосохранение и отказ, local mark/verify. |
| UI-T02 | Определён наполненный стенд, чистый тестовый владелец, реальный тег, свой разрешённый внешний origin, серверная заглушка модели и владелец проверки. | Отдельная квитанция фактического наблюдения с экрана установки и внешней страницы, видимых действий, проверенных HTTP и `first_config`/`first_answer`. Приёмка U09 открыта до прогона. |
| UI-RISK-01 | Фактический ответ и текущая SSR сессия коррелируются через узкий `X-Sufler-Claim-Context`, одноразовый slot и TTL. URL флаги игнорируются. Backend JSON и HTTP-статусы прежние. | Прямой/устаревший URL, повтор, истечение, смена аккаунта, отдельная вкладка, отсутствие storage и отказ claim. При недоступном storage отказ остаётся в AuthForm с продолжением. |
| UI-RISK-02 | Новая форма отправляет URL в POST, legacy `?url` сохраняет явный совместимый запуск и очищается. Новые ключи непрозрачны, сохраняется только безопасный origin, старый сырой префикс очищается. | Маркеры userinfo/path/query/fragment в новых URL, ключах, значениях и артефактах отсутствуют. Безопасный повтор получает прежний UUID, retry/PDF остаются без автостарта. |

Изменены требования, два proposed ADR, shift-left, доменная модель, архитектура, пять Mermaid-схем, OpenSpec design и спецификации onboarding/preview-workspace. `changedScope` в [машинной дельте](03.5-author-delta.json) также называет проверенные затронутые зависимости. ### Оценка новых рисков

- Двухпоточное внедрение заголовка может лишить пользователя свежего уведомления. Согласованы оба производителя, server-only helper и потребитель. Отсутствие корректной пары оставляет действительный список и PDF без утверждения об успехе. Ошибка сохранения при отказе записи остаётся видимой в форме. Проверяется в UI-RISK-01.
- Короткий браузерный контекст теряет сложный адрес и может быть недоступен. Пользователь получает ручной ввод, безопасные корневые адреса повторяются с прежним UUID, старый префикс удаляется. Исторический URL может присутствовать в первом входящем запросе, новые переходы его не создают. Проверяется в UI-RISK-02.
- Подмена транспорта модели может быть принята за доказательство работы внешней модели. Стенд отделяет реальные HTTP/события от синтетической модели и работает без доступного сетевого выхода к платным поставщикам. Это часть UI-T02.

Дополнительных открытых условий сверх первоначальных восьми автор не выявил. Оригинальные условия остаются открыты до независимой проверки.
